## Замечания

### 1. MAX отклоняет пустое подтверждение нажатия кнопки

Подтверждено рабочими логами: 7 предупреждений за проверенное окно последних 2 часов,
ошибка `400: Invalid request. message or notification required`.
В `src/max/max-client.ts:119` при отсутствии текста отправляется пустой объект.
Быстрые обработчики нередко возвращают undefined; `src/bot/handlers/helpers.ts:36`
подавляет ошибку подтверждения, поэтому действие может завершиться, хотя MAX
не получил корректного подтверждения нажатия. Требуется непустой безопасный ответ
по умолчанию и проверка этого контракта в тесте. Это подтверждённый дефект интерфейса.

### 2. Нет собственного ограничения размера скачиваемого вложения

`src/max/max-client.ts:160` загружает весь ответ через arrayBuffer, затем создаёт Buffer.
Есть тайм-аут 30 секунд, но нет ограничения числа полученных байтов. Для ответов
сотрудников поддерживаются файлы, поэтому крупное вложение может существенно
увеличить потребление памяти. Исчерпание памяти на рабочем сервере не наблюдалось;
это обнаруженный по коду риск устойчивости. Нужны лимит и прерывание чтения потока
при его превышении, понятное сообщение пользователю. Массовый поток реальных MAX
сообщений и предельные размеры вложений в этом аудите не моделировались.

### 3. Предупреждения безопасности зависимостей

`npm audit --omit=dev`: 5 затронутых пакетов — 3 high и 2 moderate, critical 0.
Причины — две уязвимости, учитываемые также у родительских пакетов:

- [deepmerge-ts: рекурсивные структуры](https://github.com/advisories/GHSA-ggr8-5vv4-36mx).
  Путь зависимостей: prisma → @prisma/config → deepmerge-ts. Объявленное исправление — 8.0.0.
  Advisory требует циклических объектных графов; обычный JSON не создаёт такую структуру.
  В просмотренном коде обращения жителей не передаются в этот механизм конфигурации.
- [uuid: границы буфера в v3/v5/v6](https://github.com/advisories/GHSA-w5hq-g745-h8pq).
  Путь: exceljs → uuid. В просмотренном ExcelJS используется v4 без пользовательского
  выходного буфера, поэтому описанный уязвимый вызов в этом сценарии не найден.

Вывод о недостижимости этих путей из обычного обращения — оценка по просмотренному
коду, а не гарантия отсутствия всех способов эксплуатации. Обновление зависимостей
нужно провести с проверкой совместимости и полным прогоном; автоматический downgrade
ExcelJS, предлагаемый npm, без проверки применять не следует. В аудит зависимости
не обновлялись.

# Автоматические права и справка рабочего чата

Участие в настроенном рабочем чате даёт сотруднику необходимые права внутри него.
Ручное добавление каждого сотрудника и повторное вступление существующих участников
не нужны. `/info` и `/help` показывают инструкцию для текущего чата; `/whoami`
дополнительно показывает автоматически полученные права.

## Правила

- Распределение: DISPATCHER. Согласование: APPROVER. Активная профильная группа:
  RESPONDER. Группа с прямым ответом дополнительно получает DISPATCHER в своём чате
  для сохранения существующего правила отправки без согласования.
- Чат технических предупреждений: `incident.lookup` и новая `delivery.manage`.
  Доступны `/delivery_status`, `/delivery_errors`, `/delivery_retry`; ADMIN не выдаётся.
- Источник прав — chat_id из проверенного события MAX и актуальная конфигурация.
  В личном диалоге и посторонних группах автоматических прав нет. `User.roles`
  хранит только ручные роли; существующие ручные роли и роли из окружения сохраняются.
- Права не копируются между чатами. Отключение/перепривязка группы применяется
  при следующем действии без синхронизации участников и удаления старых записей.
- Поиск обращения, история и повтор доставки в профильной группе ограничены
  обращениями именно этого чата. Ручной ADMIN сохраняет административный доступ.
- Для отзыва доступа участника нужно удалить его из рабочего чата. Снятие ручных
  ролей командой `/role ... -` само по себе не отменяет права участника.
- На `user_added` отправляется короткое приветствие с подсказкой `/info`.
  Входящая очередь и ключ исходящей отправки защищают от обычной повторной доставки
  одного события. На `user_removed` очищается только сессия этого человека в этом
  чате. Глобальные ручные роли не удаляются. Резерв распределения при выходе
  освобождается по существующему сроку 15 минут.
- Вступления ботов, каналов и посторонних групп не вызывают приветствий.
  Для событий вступления/выхода бот должен быть администратором рабочего чата.
  Пропуск события не блокирует права: они определяются на каждом действии.

## Проверка

Новый набор `working-chat-access.test.ts`: 9 интеграционных сценариев на отдельной
PostgreSQL `incident_test` с имитацией MAX. Проверены полный цикл распределения,
ответа и согласования без ручных ролей; вступление и повтор события через настоящий
SDK-диспетчер и outbox; существующие участники; выход; перенос/отключение группы;
границы прав; инструкции для разных чатов и совмещение назначений чата.

Полный прогон: 321 успешно, один старый тест маршрутизации файлов потребовал
добавить в заглушку конфигурацию и поиск рабочей группы. После исправления заглушки
повторно пройдены все 32 теста трёх затронутых наборов. Совокупно проверены 322 теста
в 52 файлах на итоговом рабочем коде; typecheck и build успешны.
Тестовые сообщения в рабочие MAX-чаты не отправлялись.

Перед обновлением диагностика подтвердила права администратора бота во всех
53 настроенных рабочих чатах: 50 профильных и 3 служебных. Doctor: 62/62.

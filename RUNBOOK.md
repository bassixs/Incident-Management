## 3. Грабли, на которые уже наступили

Здесь то, что стоило времени и наверняка встретится снова.

### 3.1 Сертификаты MAX — самое важное

`*.max.ru` подписан цепочкой **Russian Trusted Sub CA → Russian Trusted Root CA**
(Минцифры). Этого корня нет в стандартном наборе CA, поэтому любой вызов MAX API
падает с `fetch failed`, при том что остальной HTTPS с сервера работает.

Корень лежит в `deploy/russian-trusted-ca.pem` и подключается **только к
процессу бота** через `NODE_EXTRA_CA_CERTS` — в системное хранилище не ставится
и на другие контейнеры не влияет. В `docker-compose.yml` это уже настроено.

**Для любого ручного запуска на хосте переменную надо задать самому:**

```bash
NODE_EXTRA_CA_CERTS=/opt/incident-bot/deploy/russian-trusted-ca.pem npm run doctor
```

`/etc/profile.d/max-ca.sh` существует, но **неинтерактивная SSH-сессия его не
читает** — скрипт, запущенный через `ssh host "команда"`, переменную не увидит и
упадёт на `fetch failed`. Один раз это уже привело к тому, что скрипт привязки
чатов снял две существующие привязки и умер на первой же проверке. Повторный
прогон с переменной всё восстановил, но осадок остался: **всегда указывайте
переменную явно.**

### 3.2 Составные сообщения в MAX

Проверено на живом API, а не по документации:

| Что | Результат |
|---|---|
| текст + фото + кнопки в одном сообщении | **работает** |
| правка сообщения без поля `attachments` | фото и кнопки **сохраняются** |
| правка с передачей `attachments` | список заменяется целиком |

Отсюда три метода в `MaxMessageService`: `send` (всё одним сообщением),
`editCardText` (правит текст, вложения не трогает), `finalizeCard` (гасит
карточку: ни медиа, ни кнопок). Разносить текст и фото по разным сообщениям, как
было сделано изначально, не требуется — второе сообщение появляется только если
в ответе одновременно и фото, и файл (MAX группирует вложения по типу).

### 3.3 Имя модели AI

В URL на сайте AITunnel модель называется `gpt-5-6-luna`, а в API — **`gpt-5.6-luna`,
через точки**. На дефисах приходит `модель не найдена`. Каталог моделей всегда
можно перепроверить:

```bash
curl -s https://api.aitunnel.ru/v1/models -H "Authorization: Bearer $AI_API_KEY"
```

`gpt-5.6-luna` — reasoning-модель: рассуждения тратят тот же бюджет токенов, что
и ответ. Клиент ловит обрыв по `finish_reason: length` и падает явно, а не
отдаёт обрезанный JSON наверх.

### 3.4 tsx не проверяет типы

`npx tsx script.ts` выполнит код с ошибкой типов, а `npm run build` на ней
упадёт. Один раз так и вышло: скрипт отработал, а сборка образа сломалась бы на
следующем деплое. **Перед деплоем всегда `npm run typecheck`** (или `npm run
check`, который делает typecheck + сборку + тесты).

Проследить обращение целиком — по номеру, он есть в каждой строке лога:

```bash

```

### Обновление кода

```bash
cd /opt/incident-bot
# залить новые src/ tests/ prisma/
npm run typecheck
docker compose --profile tls up -d --build app
```

Миграции применяются автоматически при старте контейнера.

### Управление сферами — без перезапуска

```
/categories                       список с группировкой по готовности
/category_chat ROADS <CHAT_ID>    привязать чат
/category_name ROADS Дороги       переименовать (код не меняется)
/category_off ROADS               скрыть из выбора
/category_add NEWCODE Название    добавить новую
```

Сфера без чата диспетчеру **не показывается** — кнопки, которая упадёт после
нажатия, быть не должно.

### Резервное копирование

Настроить регулярный дамп (сейчас его нет):

```bash
docker compose exec -T postgres pg_dump -U incident -d incident -Fc > backup-$(date +%F).dump
```

Отдельно — каталог вложений (`MEDIA_STORAGE=local`, том `incident-bot_uploads`).

## 7. Что решили и почему

Короткие обоснования, чтобы не переоткрывать вопросы заново.

**26 сфер выбираются страницами по 6.** Один список на 27 кнопок — длинная
прокрутка на телефоне. «Не знаю» закреплено сверху на каждой странице: выбор
пользователя по §8 ТЗ всё равно только подсказка, а ИИ на этих формулировках
даёт 90–98%.

**AI — второй провайдер, а не замена.** `AI_PROVIDER=anthropic|openai`
переключает реализации, обе живут рядом. Схема ответа одна на обе: zod-описание
конвертируется в JSON Schema для строгого режима OpenAI, так что при смене
вендора структура не разъедется.

**SDK `openai` не ставили.** Нужен ровно один эндпоинт; свой адаптер на `fetch` —
это ~150 строк вместо мегабайтов зависимости, и он честно показывает формат
запроса.

**Отчёты — кнопками.** `/report` без аргументов показывает периоды; ручной ввод
принимает `01.08.2026 - 10.08.2026` в любом написании. Прежний синтаксис
(`/report 7d`, ISO-даты) сохранён, чтобы не ломать скрипты и привычки.

**Права проверяются при нажатии, а не при показе кнопок.** Карточка остаётся в
истории чата, нажать её может кто угодно позже — поэтому факт существования
кнопки ничего не разрешает.

**Сфера без чата скрыта от диспетчера, но это не ошибка в доктора.** Это
состояние внедрения; если считать его ошибкой, доктор будет вечно красным и
перестанет что-либо значить.

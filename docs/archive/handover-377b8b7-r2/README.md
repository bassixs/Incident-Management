# Исторический комплект update-377b8b7-r2

Архив исходников инструментов и публичных копий инструкций пакета
**Na-svyazi-region40-update-377b8b7-r2**, приложение
`377b8b7837037e8aaad4e98530d02588f086edb2`. Это НЕ полный передаточный архив,
НЕ действующая инструкция для main и НЕ подтверждение совместимости с `76da343`.
Исторический `deploy/handover/` относится к другой, ещё более ранней редакции.
Оба набора сохранены раздельно; действующие инструкции не заменены.

## Состав и границы

- `config/`: шесть исходных файлов. Скрипты сохранены побайтово; у YAML только
  окончания строк CRLF заменены на LF. Логика и значения не изменены.
  `build-label.yml` намеренно содержит старый SHA: его нельзя применять к новой сборке.
- `checks/`: существующие регрессии без изменения логики: 404/повторы удаления,
  сбор ID из массивов, сохранение журнала, защита панелей и ожидание готовности.
- `package.py`: исходный сборщик r2, рассчитанный на старые входные материалы,
  manifest и acceptance.json. Это сохранение истории, не новый универсальный сборщик.
- START-HERE.md, CLEANUP.md, PATCH-TOOLS.md, RELEASE-NOTES.md: исторические тексты
  с добавленной маркировкой и исключением частного ID получателя отчёта.
- `provenance.json`: относительные пути источников и SHA-256 исходных файлов.
  Это происхождение исходников, а не контрольные суммы передаточного ZIP.

Не включены project/, verification/, результаты старых запусков, ZIP, дампы,
вложения, .env и приватные настройки. `set-status-env.py` содержал фиксированного
получателя и намеренно исключён; не заменяйте его фиктивным общим получателем.
В публичном тексте его шаг обозначен как ручная настройка значений своего окружения.
Остальные команды сохраняют исторические допущения. Пример пути
`$HOME/incident-transfer` и имя Compose-проекта `incident-bot` не определяют
параметры другой установки. Сначала сверяются её фактические пути и конфигурация.

Исторические сценарии телефона (системный контакт и закрытый просмотр) уже
изменены в PR №2; новые черновики и их версии появились в PR №3. Эти документы
не должны возвращать прежние требования. Перед любым повторным использованием
cleanup необходима отдельная проверка схемы, новых связей/черновиков и outbox.
Присутствие файла в Git не разрешает очистку реальных данных.

## Проверки без сервера и сети

Для синтаксиса: `node --check <файл.cjs>`, `bash -n <файл.sh>`;
Python разбирается через `ast.parse`, а не запуском сборщика.
После наличия зависимостей проекта локальные проверки с имитацией выполняются
из корня тестовой рабочей копии (они не читают .env):

```bash
R2="$PWD/docs/archive/handover-377b8b7-r2"
CLEANUP_TOOL="$R2/config/cleanup-test-data.cjs" \
WAIT_HELPER="$R2/config/wait-ready.sh" \
node --test "$R2/checks/cleanup.test.cjs" "$R2/checks/ready-probe.test.cjs"
```

`common.cjs` находит установленный Prisma через package.json текущего каталога;
тесты подменяют БД и MAX, реальный PrismaClient не создаётся. В фикстурах номера,
имена, ID и тексты синтетические, не данные жителей.

Для существующего Bash-теста ожидания нужна временная папка с таким размещением:

```bash
CHECK_STAGE=$(mktemp -d)
mkdir "$CHECK_STAGE/config"
cp "$R2/checks/wait-test.sh" "$CHECK_STAGE/wait-test.sh"
cp "$R2/config/wait-ready.sh" "$CHECK_STAGE/config/wait-ready.sh"
bash "$CHECK_STAGE/wait-test.sh"
```

Он подставляет fake docker в PATH. Не запускайте wait-ready.sh отдельно ради
этой проверки: отдельно он обращается к настоящему Docker. Временные результаты
и fake-docker не добавляются в Git.

`test-cleanup.cjs` и `array-integration.cjs` — сохранённые интеграционные сценарии
PostgreSQL для **изолированной** базы `incident_tools_r2_test`, `/app` с приложением
исторической версии и `/ops` с инструментами. Они изменяют синтетические записи
и файлы. Имя базы само по себе не доказывает изоляцию; старый серверный test.sh
не перенесён. В этом PR SQL-сценарии только проверены на синтаксис, не запущены.

## Сборщик

`package.py` запускается из корня отдельной рабочей копии, ожидает исторический
`output/update-main-377b8b7-r2/Na-svyazi-region40` (project, verification и остальное),
предыдущий ZIP из `output/update-main-20260930` с зафиксированной суммой и Git-объект
377b8b7. Эти закрытые/генерируемые входы не публикуются. Он проверяет побайтовое
совпадение project и не разрешает замену существующего ZIP. Внутри есть утверждения
о прежних проверках — это исторические результаты, не тесты, запускаемые сборщиком.
Не использовать его для новой версии и не переносить эти утверждения в новый отчёт.

# Еженедельный отчёт работающего бота

Настройки: `BOT_STATUS_USER_IDS` — положительные MAX user ID через запятую,
`BOT_STATUS_TIME` — HH:mm, `BOT_STATUS_WEEKDAY` — monday…sunday.
Пустой список получателей отключает планирование и отправку ожидающих отчётов.
В общем `.env.example` список пуст. Получатель должен заранее открыть личный
диалог с тем ботом, который отправляет отчёт. Действующий `.env` не переписывается.

Расписание всегда использует Europe/Moscow, независимо от ОС и APP_TIMEZONE.
По умолчанию — понедельник 08:00. Планировщик проверяет расписание при запуске
и раз в минуту. Пропущенное время восполняется только в тот же московский день,
с фактическим временем проверки. Прошлые недели не восполняются.

Обязательные проверки:

- SELECT 1 к БД;
- FAILED и ожидающие повторной попытки задания inbox/outbox;
- PROCESSING/SENDING без времени блокировки либо с блокировкой от 120 секунд;
- PENDING без попыток, ожидающие положенного времени обработки более 15 минут;
- GET /me MAX API;
- наличие ожидаемой WEBHOOK_URL, состав событий и отсутствие иных подписок.

Свежие PENDING не считаются проблемой. Для каждой группы проверок действует
ограничение ожидания 10 секунд. Ошибка, тайм-аут или неизвестный список событий
подписки не считаются успешной проверкой. Прямое соединение MAX с нашим HTTPS
endpoint этим не проверяется. Используется существующий MaxClient; авторизация
и проверка TLS не меняются. Официальное описание подписок:
https://dev.max.ru/docs-api/methods/POST/subscriptions.

Сообщение содержит только время, фиксированные описания проблем и счётчики.
Телефоны, содержимое сообщений, токены и исходные ошибки не включаются.
Если проблем нет, текст при проверке в 08:00:

> Доброе утро! Чат-бот «На связи_регион40» работает. По автоматической проверке на 08:00 МСК проблем не обнаружено.

Недельная отметка SystemSetting и задания OutboundMessage всем получателям
записываются одной транзакцией. Уникальные ключи защищают от повторного
планирования при перезапуске и параллельных экземплярах. Отдельная ошибка доставки
не блокирует другого получателя. Задания использует существующий outbox с его
ограниченным числом повторов; исчерпавшие повторы остаются FAILED для диагностики.

Перед каждой попыткой проверяются получатель и срок актуальности. Отложенная
доставка в другую минуту явно указывает дату и время исходной проверки. После
московской полуночи отчёт не отправляется. Просроченные/отключённые задания
завершаются без отправки: SENT, пустые sentAt/firstMessageId, фиксированная причина
в lastError. Сохраняется ключ подавления повторов. Повторное включение в ту же
неделю не создаёт второй запуск; изменение списка после запуска действует со
следующей недели.

Это однократное создание логического задания, а не обещание физической доставки
строго один раз: при принятии сообщения MAX и потере ответа обычный механизм
повтора outbox/MaxClient может отправить копию. Атомарной транзакции БД–MAX нет.

Остановленный бот не может сообщить о своей остановке. При полностью недоступной
БД нельзя сохранить и отправить отчёт через outbox: планирование повторяется
в пределах того же дня после восстановления. Сохранение отчёта не заменяет
внешний мониторинг. Это не живой прогон подачи и обработки сообщения жителя.

Миграций БД нет. Рабочие чаты не используются для отчётов.

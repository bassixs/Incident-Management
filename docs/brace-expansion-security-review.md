## Изменение и цепочки

Изменены только две записи package-lock.json, в пределах разрешённых родительскими
пакетами semver-диапазонов. Нового override нет; ExcelJS и minimatch не обновлялись.
Обычный `npm update brace-expansion --package-lock-only` обновил вложенную 2.x,
но сохранил корневую 1.x. Для неё удалена только её запись lock-файла и выполнен
`npm install --package-lock-only --ignore-scripts`; npm сформировал версию,
URL пакета и integrity. Diff проверен: других изменений дерева нет.

Наличие уязвимых пакетов в production подтверждено. Эксплуатация через сообщение
жителя не подтверждена: приложение не передаёт пользовательские glob-шаблоны
в minimatch/brace-expansion. Excel-отчёт использует Workbook.xlsx.writeBuffer(),
который в ExcelJS 4.4.0 идёт через ZipWriter/JSZip; archiver используется другим,
потоковым экспортом WorkbookWriter. Это оценка найденного пути, а не доказательство
отсутствия любых способов эксплуатации.

## Проверки

- Чистая `npm ci`: обе установленные копии совпадают с lock-файлом.
- `node tools/check-brace-expansion.cjs`: проверка каждой копии, обычного раскрытия
  шаблона, глубокой вложенности и последовательности правых скобок. Опасные входы
  выполняются в отдельных процессах с ограничениями времени и памяти.
- Регрессии: новый unit-тест и существующий XLSX round-trip.
- Typecheck и сборка приложения.
- В конечном production-слое Docker проверяется тот же скрипт, без сети.

Итог полного набора тестов и аудита после отдельного обновления dev-зависимостей
фиксируется в dev-dependencies-security-review.md. Рабочие боты, вебхуки и данные
не используются для этих проверок.

# Контекст обращения и версии для исполнителя

База: `e32026987496f71889f61f1d298f2469b60d16e2`.
Работа выполнена локально и в изолированной PostgreSQL с имитацией MAX.
Производственный сервер, токен, данные и резерв не использовались.

## Что уже было и что переиспользовано

`/history` показывает журнал действий из IncidentHistory. Это не архив полных
текстов и файлов ответов; команда остаётся без изменений. Для нового просмотра
используются существующие IncidentAnswer (version, createdAt, text, revisionReason)
и AnswerAttachment. Замечание конкретной версии читается только из её записи.
Incident.revisionReason показывается отдельно как последнее замечание по обращению;
оно никогда не подставляется в историю другой версии.

Переиспользованы репозиторий с версиями, форматирование дат, авторизация профильного
чата, проверка членства личной работы, загрузчик вложений и транспорт сообщений
с ограничениями MAX. Схема, миграции и формат deliveryProgress не меняются.

## Экраны и переходы

Основная и возвратная карточки содержат короткие выдержки исходного обращения,
последнего замечания и последней сохранённой версии ответа. Полные значения не
меняются. На активных этапах есть кнопка «Обращение и доработки».

Просмотр открывается в отдельном текстовом сообщении. Переходы редактируют только
это сообщение, а не оригинал рабочей карточки и не сообщения с фотографиями.

- Исходный текст → страницы по 2400 Unicode-символов → Назад.
- Исходные фотографии → список всех вложений, по шесть кнопок → одно вложение по нажатию.
- Последний сохранённый ответ → текст версии, дата создания, замечание этой версии,
  её фотографии и файлы. Исторические версии не содержат рабочих действий.
- История → по шесть версий, от новых к старым → выбранная версия. Возврат ведёт
  на страницу списка с этой версией; из замечания/вложений — к прежней странице её текста.
- Последнее замечание полностью → полная сводка обращения без предположения о номере версии.
- Мой незавершённый ввод → подготовленный сотрудником текст, не отправляя его.
  Личный незавершённый проект не раскрывается в общем чате.
- К текущей рабочей карточке → актуальное состояние. В чате отправляется свежий
  компактный вид с ответом-ссылкой на сохранённый MID рабочей карточки; её ID не
  заменяется. Лично открывается штатная текущая карточка без выбора другого обращения.

### Примеры (вымышленные данные)

Карточка возврата:

```text
↩️ ОТВЕТ ВОЗВРАЩЁН НА ДОРАБОТКУ

№ INC-TEST
Возвращена версия 7

Исходное сообщение:
Не работает освещение у дома.
Исходных вложений: 2

Последнее замечание согласующего:
Укажите дату выполненных работ.

Последняя сохранённая версия ответа — 7:
Освещение восстановлено.

[Обращение и доработки]
[Исправить ответ]
```

Версия и связанное замечание открываются отдельно:

```text
INC-TEST · Только просмотр
Версия 7 · 07.10.2026 10:30 · историческая · 1/2

Освещение восстановлено…

[Следующая страница →]
[Замечание к этой версии] [Вложения (2)]
[Назад] [К текущей рабочей карточке]
```

```text
INC-TEST · Только просмотр
Замечание к версии 7 · 1/1

Укажите дату выполненных работ.

[Назад → прежняя страница версии 7]
[К текущей рабочей карточке]
```

Подписи внутри квадратных скобок описывают кнопки; фактическая кнопка возврата
называется «Назад». Дата отображается существующим форматтером проекта.

## Защиты и сохранность

Просмотр не вызывает claim/take, submit/approve, выбор обращения или очистку сессии.
Статусы, назначения, сроки, версии, доставленность и подготовленный ввод не меняются.
Истечение закрепления не запрещает чтение члену текущей организации и не продлевает
закрепление; рабочие действия по-прежнему требуют штатной проверки актуального состояния.

Перед каждым запросом заново проверяются организация и активность чата. Даже ADMIN
не может открыть сведения в прежнем профильном чате после переназначения. В личном
режиме проверяются владелец PrivateWorkItem и текущее членство через MAX GET. Перед
отправкой после чтения файла и ожидания транспорта проверки повторяются.

Один служебный SystemSetting на пользователя/исходный чат/режим хранит только ID,
токен экрана, MID, цикл назначения и маршруты кнопок. В нём нет копий текстов или
телефонов. Короткая блокировка сериализует переходы; токен потребляется до внешнего
запроса, а новый сохраняется только после подтверждения. Старый, повторный или
задержанный callback не становится бизнес-действием. Смена версии ответа не меняет
ID просматриваемой исторической версии; возврат читает актуальное состояние.

Вложения отправляются по одному по явному запросу сотрудника. Все исходные записи,
в том числе старые наборы более четырёх фото, остаются целыми. Недоступный файл,
отозванная фотография MAX, отсутствие версии/замечания и неполная история объясняются.
Отсутствие записи не выдаётся за доказательство отсутствия замечания в прошлом.

## Совместимость и ограничения

- Нет миграции. Резерв не изменён: новой кнопки и просмотра в нём нет; это не
  подтверждение его совместимости со всеми остальными изменениями main.
- Старые карточки массово не редактируются. Новая кнопка появится на новых карточках
  и при штатном обновлении активных карточек. Для старого экрана можно заново открыть
  обращение штатным способом; уже сохранённые ответы и фотографии не переотправляются.
- Сохраняются отдельный прямой маршрут REGION_KALUGA, исключение публичной подписи,
  доставка частями и защиты PR №16–17. Новых предупреждений о сроках нет.
- Просмотр не меняет сообщения, уже полученные сотрудниками. Отзыв доступа нельзя
  атомарно объединить с HTTP MAX: ответ на уже ушедший запрос может прийти поздно.
  После обнаружения смены назначения такой экран не активируется.
- При ошибке доставки/редактирования нужно заново открыть просмотр. Подготовленный
  ответ остаётся на месте. При неизвестном результате отправки вложения показывается
  предупреждение проверить сообщения; автоматического повторного запроса нет.
  Транспортные повторы MAX не гарантируют отсутствие дублей при потерянном ACK.
- Несохранённый в боте текст в редакторе клиента MAX недоступен серверу. Просмотр
  показывает только уже полученный/сохранённый ввод. Вложения такого ввода остаются
  в штатном предварительном просмотре; архив версий показывает сохранённые вложения ответов.

## Проверки

Новый интеграционный файл использует обычные входящие callbacks, настоящую PostgreSQL
и mock MAX. Проверяются оба режима, семь циклов, восемь версий, длинный Unicode-текст,
соответствие замечаний и файлов версии, девять исходных фотографий, отсутствие истории,
сохранность сессий/черновиков/выбора, возвраты, истечение и смена закрепления, назначения,
версии, прав, повторные/задержанные нажатия, перезапуск, ошибки и неизвестные результаты.
Весь набор unit и связанные файлы доставки, очередей, личной работы и навигации запускаются
в Actions; точные SHA и результаты находятся в PR.

Первый прогон выявил добавление кнопки просмотра на завершённых карточках — устранено;
прежнее снятие всех действий сохранено. Ожидания активных клавиатур дополнены ровно
новой кнопкой. Две старые unit-фикстуры содержали только deliveredAt без текста ответа:
для такого неполного значения добавлено явное сообщение об отсутствии текста. Проверка
отключённого чата подтверждает штатное молчание, а не отправку отказа в посторонний чат.

Дополнительная проверка создаёт семь возвратов настоящими AnswerService/ReviewService,
затем открывает каждую версию и её замечание в обоих режимах. Технический отказ
первой отправки экрана не подавляется: он остаётся ошибкой для durable inbox после
уведомления сотрудника. Новое явное открытие восстанавливает просмотр без потери ввода.

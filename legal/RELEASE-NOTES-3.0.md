# Редакция 3.0: минимизация данных жителей

Окончательное решение владельца: без ФИО, без телефона, без передачи контакта и без подтверждения документов. Из промежуточного варианта с телефоном ничего не включается.

Первый шаг — выбор темы. Связь с автором и доставка ответа используют ID MAX. Сохраняются обращения, допустимые фото-токены и необходимые служебные сведения. Рабочие роли и данные сотрудников для указания ответственного сохраняются отдельно от профиля жителя. Реквизиты жителя в прежних столбцах не записываются; старые столбцы оставлены для совместимости схемы, а не для сбора данных.

Текст проходит локальную проверку до входящей очереди и на этапе создания обращения. При совпадении сохраняется только технический признак отказа; контакт и пересылка жителя также отклоняются. Профильное имя и имя пользователя MAX удаляются из события. Содержимое успешно обработанных входящих событий очищается. Правила распознавания не гарантируют обнаружение всех ФИО и других персональных данных.

До распределения обязательна проверка всего текста и каждого фото сотрудником. Есть отдельная кнопка подтверждения проверки; действие защищено рабочими правами и закреплением обращения. Распределение без проверки запрещено на уровне транзакции. Причина отказа «Персональные данные» проходит обычный предварительный просмотр и подтверждение. Для отклонённых сообщений удаляются текст и ссылки на вложения из обращения и связанные задания доставки. Независимые копии в MAX, выгруженные отчёты и архивы у других получателей требуют отдельного контроля оператора.

`LEGAL_CONSENT_REQUIRED=false`. Новые записи LegalAcceptance не создаются даже при нажатии старой кнопки. PDF по прежнему адресу согласия сообщает, что подтверждение отключено, и не является формой согласия. Правила и политика обновлены до 3.0.

ID MAX вместе с обращениями не является гарантированным полным обезличиванием. Оператор обязан определить правовое основание работы без согласия до запуска; отключение кнопки само по себе такого основания не создаёт. Сохраняются организационные вопросы из предыдущего аудита: полномочия оператора, хранение в РФ, доступы, сроки и удаление копий. Перед запуском требуется проверка Минцифры.

Утилита `node dist/scripts/reset-resident-data.js` показывает объём старых данных; `--confirm` выполняет разрешённую владельцем очистку. Запускать только при остановленном приложении. Обращения, профили жителей, согласия, сессии и задания очищаются; рабочие группы, категории, роли и счётчик номеров сохраняются. Удаление известных рабочих сообщений MAX — отдельные API-вызовы без запуска бота. Права старого бота могут уже отсутствовать; результат сообщает количество неподтверждённых удалений. Личные переписки жителей не удаляются. Копии на новом сервере и у получателей этой утилитой не очищаются.

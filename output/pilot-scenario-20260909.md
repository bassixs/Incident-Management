# «Искра»: сценарий живого пилота в MAX

Подготовлен 09.09.2026. Пилот ещё не проведён. Участников и время собирает руководитель проекта. План: 15-20 жителей, два сотрудника распределения, два исполнителя обычной организации, исполнитель организации с прямым ответом, согласующий и наблюдатель. Достаточно 60-90 минут. Наблюдатель ведёт журнал; сотрудники работают по инструкции из /info.

## Перед началом

1. Выбрать окно и предупредить сотрудников о тестовых обращениях. Использовать только аккаунты участников и согласованные рабочие чаты. Каждое обращение начинать с «ПИЛОТ P01» и далее своим номером P02-P20. Не маскировать тест под реальную просьбу о помощи.
2. Проверить /info и открытие PDF в обоих профильных чатах. У сотрудников должны открываться карточки; у жителей - личный диалог с ботом. Жители сами вводят требуемые сведения и подтверждают правила.
3. Подготовить нейтральные фото без посторонних людей и документов. В журнале хранить только P-номер, номер INC, время и результат, без телефонов, ФИО и медиатокенов.
4. Зафиксировать время начала с часовым поясом, состояние /ready, /delivery_errors и отчёт delivery-metrics. Не менять параллельность очередей (8/8) и лимиты ради красивого результата.

## Первая волна: шесть контрольных обращений

| Сценарий | Действия | Ожидаемый результат |
|---|---|---|
| P01: обычный ответ | Житель создаёт обращение без фото. Распределитель назначает организацию. Исполнитель берёт в работу, готовит текст. Согласующий утверждает. Житель ставит оценку. | Один номер INC; статусы «Свободное», «В работе», «На согласовании», «Отработано». После взятия исчезает «Взять в работу», на согласовании и после доставки нет кнопок подготовки ответа. Ответ и оценка относятся к P01. |
| P02: фотографии | Житель прикрепляет два разных фото. Исполнитель отвечает текстом с фото одним сообщением. | Обе исходные фотографии открываются до и после каждого обновления карточки. Фото ответа приходит нужному жителю. Нет смешения исходных фото и фото ответа. |
| P03: доработка | Согласующий возвращает ответ с замечанием. Исполнитель нажимает «Исправить ответ» и отправляет новую полную версию с фото. | Исходная карточка показывает «На доработке» с одной кнопкой исправления; затем снова согласование. Жителю доставлена окончательная версия. Срок обращения от возврата не продлевается. |
| P04: прямой ответ | Распределить обращение в организацию с прямой отправкой. Исполнитель отправляет окончательный текст. | Ответ проходит без отдельного согласования. До подтверждения доставки нельзя считать его отработанным; после подтверждения кнопок нет. |
| P05: одновременная работа | Два распределителя одновременно берут следующее обращение. Два исполнителя пытаются взять одну исходную карточку. | Распределение не выдаёт один элемент двум сотрудникам; повторное действие на уже взятом обращении даёт понятный ответ и не создаёт вторую карточку/ответ. Проверить исполнителя через /incident. |
| P06: прерывание ввода | Житель начинает черновик, открывает /info, возвращается и исправляет ввод до подтверждения. Исполнитель начинает подготовку, отменяет её предусмотренной кнопкой, затем начинает заново. | Справка не теряет черновик. После отмены нет случайной отправки. Новое действие и ответ относятся к нужному обращению. |

Статус «Ожидает доставки» может смениться слишком быстро, чтобы попасть в снимок экрана. Это не ошибка. Задержки, недоступные токены и аварийное выключение проверяются на изолированном стенде; специально ломать доставку на живых участниках не нужно.

## Вторая волна: оставшиеся участники

После успешных P01-P06 запустить остальных с интервалом 10-20 секунд, затем одну согласованную группу из 5 человек одновременно. Смешать обращения с фото и без, обычное согласование и прямую отправку. Каждый участник создаёт одно обращение. После ответа проверить /my и оценку. Наблюдатель сверяет номера во всех чатах и отсутствие чужих текстов/фото.

## Журнал

Время фиксировать с секундами по Москве. Для каждого P-номера скопировать строку:

| P | INC | Подтверждено жителем | Карточка распределения видна | Назначено | Карточка профиля видна | Ответ согласован/принят напрямую | Ответ виден жителю | Фото открываются | Статусы/кнопки верны | Оценка принята | Замечание |
|---|---|---|---|---|---|---|---|---|---|---|---|
| P01 | | | | | | | | | | | |

При сбое записать точный шаг, INC и время, не повторять действие многократно. При чужих данных, потерянном обращении или повторной доставке остановить следующую волну и передать номер наблюдателю. Не удалять данные до разбора.

## Как оценить результат

- Все 15-20 подтверждённых обращений найдены по INC; каждый получил ожидаемый итог, фото и оценку без смешения пользователей и дублей.
- Статусы и кнопки совпадают с таблицей, исходные фото не пропадают.
- Нет необъяснённых FAILED/PENDING/SENDING в очередях после завершения; ошибки доставки разобраны.
- Сопоставлены наблюдаемое время в MAX и серверные p50/p95/максимум с размером выборки. Более 30 секунд на техническую отправку карточки/готового ответа - повод для разбора, а не установленное обещание SLA. Ожидание решения сотрудников считать отдельно.
- Каждый участник отвечает: «Было ли понятно, что делать дальше?», «На каком шаге потребовалась помощь?», «Что было непонятно в статусах или кнопках?».

В конце снять отчёт метрик за точное окно пилота, сохранить журнал и список замечаний. Решение о расширении принимать после разбора ошибок. Серверные метрики считают все события в выбранном окне; если одновременно шла обычная работа, отдельно отметить это в отчёте. Пилот не доказывает работу под большой нагрузкой или прочтение сообщения жителем.

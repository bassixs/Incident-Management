# Контролируемое переключение webhook — только вечером по команде

Комплект не меняет подписки; WEBHOOK_AUTO_REGISTER=false. Переключение выполняет уполномоченный оператор через утверждённый способ с Authorization в заголовке, без токена в URL или аргументах процесса. Перед POST сохранить GET https://platform-api2.max.ru/subscriptions приватно. Проверить точный старый URL, новый URL из подготовленного runtime.env, состав update_types и сохранённый WEBHOOK_SECRET. Путь берётся из WEBHOOK_PATH (обычно /webhook/max), не угадывается.

После source-stop/final-copy/restore и проверки внешнего HTTPS:
- POST /subscriptions: JSON {url: новый URL, update_types: фактически сохранённый список, secret: сохранённый секрет}. Не заменять неизвестный список случайным сокращённым набором.
- GET /subscriptions: проверить новый URL и update_types; вывод хранить приватно. При тайм-ауте записи сначала этот GET, не повторять вслепую.
- Если старый URL остался, DELETE /subscriptions?url=ТОЧНЫЙ_ПРЕЖНИЙ_URL; затем GET подтвердить единственную нужную подписку. Другие неизвестные URL — остановка для выяснения, не удалять.
- Запустить единственный target и проверить health/ready и фактическое входящее событие после ручного действия владельца.

Между переключением подписки и готовностью app возможен 502; исходный источник уже выключен. Не обещаем неограниченное хранение/повтор MAX и безусловное отсутствие потери событий в окне простоя. Сократить окно, фиксировать временные границы; неопределённые события сверять по журналам. Не использовать GET /updates/long polling параллельно webhook ради проверки.

При отмене до target start вернуть старый URL и проверить GET до согласованного возобновления исходного CID. После target start сначала текущая копия/обратный перенос, старую БД не включать.

На стенде проверяются локальный HTTP mock и отсутствие неожиданных subscription-запросов от app. Настоящая смена подписки, публичный TLS/MAX callback выполняются только вечером после разрешения; в текущей подготовке не выполнялись.

Официальные методы: https://dev.max.ru/docs-api/methods/GET/subscriptions ; https://dev.max.ru/docs-api/methods/POST/subscriptions ; https://dev.max.ru/docs-api/methods/DELETE/subscriptions . MAX требует публично доверенный HTTPS на443; самоподписанный сертификат стенда не подтверждает пригодность production webhook.

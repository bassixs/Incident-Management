# Ограничения редакции pr14-18-v1

- На рабочем сервере ничего не проверялось и не выполнялось. Settings/Compose,
  реальная политика рестарта, PostgreSQL, права и плановый backup требуют отдельной
  приватной подготовки. Новый комплект не разрешает установку.
- Поддержаны ровно три SHA из IMAGES.json и две новые миграции. Нельзя нормализовать
  иные checksums, принимать production probe за эталон или смешивать редакции.
- Активация WORKING_HOURS_V1 — отдельное решение перед запуском; оба кандидата
  одинаковы. Позднейшая активация при уже завершённой установке LEGACY этим планом
  не автоматизирована и требует отдельной подготовки.
- Неизвестная/частичная миграция оставляет приложение остановленным для разбора:
  безопасного автоматического возврата к591 после intent нет. Резерв требует
  полностью подтверждённую новую схему.
- Реальные инфраструктурные неисправности воспроизводились управляемым отказом
  команды создания и реальным контейнером exit17; это не полный набор сбоев Docker,
  диска, ядра и внезапного выключения питания.
- backup-data.py использует полный pg_dump и per-field SHA256 в одном exported
  snapshot; до180с exporter, до120с dump. На большом объёме возможен явный отказ;
  нельзя просто увеличивать пределы без оценки нагрузки. Файлы хешируются дважды;
  изменившийся набор отклоняется, его нельзя объявлять проверенной копией.
- Восстановление проверяется в отдельной network=none PostgreSQL, новые таблицы,
  enum, все поля, семьтриггеров/функция включены. Файловый архив читается полностью
  и проверяется по хешам без распаковки поверх рабочих файлов. Приложение из копии
  не запускается. Резервная копия содержит приватные данные/секреты — не публиковать.
- После запуска новые записи/изменения не игнорируются: сверка требует проверки
  истории иACK. Скрипт не доказывает корректность произвольного бизнес-перехода.
- Плановые таймеры не устанавливаются. Старый механизм нужно проверить на отсутствие
  whitelist; смена трёх metadataстрок сама по себе не доказывает его совместимость.
- Старые R4-матрицы и приложение целиком повторно не прогоняются. Проверяются
  изменённые операционные ветки, сохранность синтетических данных и реальная БД.
- ПотерянныйACK, неизвестное завершение удаления и общие дефекты main/reserve
  остаются ограничениями. Никакого предположения об успешной отправке.

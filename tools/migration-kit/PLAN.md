## Подготовка на конкретной установке — отдельное разрешение

Установочные настройки пока не содержат реальных адресов, имён контейнеров,
Docker network, БД, путей и секретов. Перед применением требуется отдельная
подготовка этих значений по чтению фактической установки. Сверить image ID по
IMAGES.json и код/lock по протоколу. Проверить SHA256SUMS и файл .sha256 архива.
Загрузить образы только после разрешения. Образ старой версии сохранить.

Настройки R4 сохраняют прежние поля и добавляют обязательный объект `migration`:
`network` (сеть существующей БД), `container` (новое уникальное имя одноразового
Prisma CLI), `manifest` (абсолютный путь schema-expectations.json),
`manifest_sha256`, `identity` из read-only schema-probe: `system`, `database`, `oid`.
Манифест должен совпадать с результатом изолированной проверки; нельзя формировать
ожидаемую новую схему путём принятия неизвестного состояния рабочей БД.
Read-only probe использует тот же неизменный runtime.env, образ основной версии
и сеть, что Prisma CLI миграций. Он не запускает приложение/MAX.
PG роль должна иметь право чтения pg_control_system(); отказ — повод разобраться,
а не убрать проверку. Проверить миграции, схему, свободное место, актуальное
резервирование, отсутствие конкурирующих операторов и других экземпляров.

## Одна контролируемая остановка

1. Свежая проверенная копия БД, файлов и конфигурации; восстановление в отдельной
   БД. Снимок ID/статусов/истории/черновиков/очередей/панелей и хешей вложений.
2. Запустить управляющий процесс через `locked-session.py --settings SETTINGS --
   COMMAND ...`; все дочерние скрипты наследуют INCIDENT_OPS_LOCK_FD. Выход
   управляющего процесса освобождает flock. Не оставлять detached-потомков с FD.
3. `stop-app.py --settings SETTINGS OLD_IMAGE RUN` — только SIGTERM, до 75 секунд,
   проверка штатного выхода. PostgreSQL/Caddy/настройки не меняются.
4. Финальная копия после остановки и сверка исходных данных; без восстановления
   старого дампа. До начала миграций отмена разрешена только через
   `resume-unapplied.py --settings SETTINGS OLD_IMAGE RUN`: тот же контейнер,
   старая фактическая схема, нет migration-intent и попыток нового запуска.
5. `migrate-app.py --settings SETTINGS RUN`. До любого запуска Prisma записывается
   общий durable `PREPARED/migration-intent.json` (fsync). После этого старый образ
   запрещён, даже если Compose старый и applied.json отсутствует. Prisma выполняет
   только две новые миграции. Успех требует exit=0, точной схемы/миграций и DB identity.
6. `apply-config.py --settings SETTINGS OLD_IMAGE MAIN_IMAGE OLD_COMPOSE_SHA MAIN_CANDIDATE RUN`.
   Затем `start-app.py --settings SETTINGS MAIN_IMAGE RUN`. Только один app.
   Перед этими действиями снова проверяются фактические миграции и схема.
7. Готовность ограничена 120 секундами; read-only schema probe имеет отдельный
   предел 30 секунд. Один тайм-аут не является доказательством дефекта. Сохранить
   журналы и проверить причину. Никаких автоматических бесконечных перезапусков.
8. Сверить данные по ID и допустимым переходам истории, все фото старых наборов,
   сохранённые progress/журнал/fence, восемь известных FAILED, очереди, панели.
   Не выполнять массовый retry, фиктивный SENT, очистку и тестовые действия с
   реальными обращениями. Ручная проверка владельцем — отдельный этап.
9. После технического успеха update-backup-metadata.py с точными прежними
   REV/IMAGE и новой парой. Освободить lock на всех выходах, выполнить проверенную
   итоговую копию; не держать резервирование выключенным до ручного теста.

## Выбор резерва и условия остановки

* До миграций: защищённая отмена на том же старом контейнере.
* `migration-intent` начат/повреждён, Prisma/SQL timeout, частичная схема,
  неясный результат, контейнер миграций работает: никакого автоматического
  старта старого или нового приложения. Сохранить доказательства, освободить
  backup.lock и разбирать отдельно. Не удалять/редактировать служебные записи
  и не использовать migrate resolve по предположению.
* Миграции точно завершены, Compose ещё старый: разрешены только main/reserve.
* Подтверждённый отказ создания/запуска: R4 recover-config.py MAIN_IMAGE
  RESERVE_IMAGE CURRENT_COMPOSE_SHA RUN reviewed-start-failure, затем start-app.py
  RESERVE_IMAGE RUN. Сохранены исходные проверки точной попытки и окна 300 секунд.
* Уже готовая основная версия с подтверждённым дефектом: новая операция RUN2,
  штатная остановка main, apply main→reserve и start reserve с текущей БД.
  Возврат reserve→main аналогичен. Никаких rollback SQL/старого дампа.
* Ошибка миграции не покрывается резервом: обе версии требуют полную новую схему.
  Установку планировать только при готовности разобрать этот отказ; гарантия
  мгновенного автоматического восстановления здесь невозможна.
* Ledger и завершённый контейнер Prisma сохраняются: они нужны последующим
  проверкам. Нельзя удалять их для разрешения запуска или создавать новый RUN
  в обход отказа.

Точные частные команды и настройки остаются будущим отдельным этапом. Этот
комплект не является разрешением на подключение к серверу или установку.
